# TikTok 博主封面图「采集 + 自动质检」完整流程说明

本文档说明 `找图片` 项目从"输入一批博主链接"到"输出分好级的封面图 + 汇总表"的**每一种处理细节**，包括每个模块、每个阈值、每一步为什么这样做。

---

## 一、项目目标

自动批量抓取 TikTok 博主的视频封面图，并按"是否能作为干净、可用的人物封面"自动分成 **A / B / C** 三档：

- **A 初筛通过**：有人脸 + 清晰 + 无水印/字幕/贴纸浮层
- **B 待人工复核**：有较轻微问题（人脸略糊、疑似水印等）
- **C 不合格**：无人脸 / 糊 / 有水印字幕 / 有贴纸浮层 / 人脸太小

> 说明：A 只是"机器初筛通过"，不代表人工最终确认；B 需要人工看一眼。

## 四、端到端数据流

```
profiles.csv (链接)
     │  read_input / parse_username  解析并去重出唯一账号
     ▼
for 每个账号 process_account():
     1) 抓「视频封面 URL」 fetch_video_covers_browser()  (Playwright 接管 Chrome，拦截 /api/post/item_list)
     2) 并发下载 download_image()  → 落到 <账号>/tmp/<post_id>_<i>.jpg
     3) SHA256 去重 sha256_file()
     4) 逐张质检 qc_image()  ★核心
          ├─ 人脸检测 InsightFace
          ├─ 模糊度 Laplacian
          ├─ 字幕/水印文字 detect_watermark + detect_text_overlay (OCR)
          └─ 贴纸/浮层 vlm_overlay.vlm_check (视觉模型)
     5) 按等级移动到 <账号>/A_初筛通过 | B_待人工复核 | C_不合格
     6) 写 checkpoint（断点续跑）
     ▼
写 Excel 汇总 summary.xlsx + passed_videos.csv(A 档清单)
```

## 五、抓取封面是怎么实现的（fetch_video_covers_browser）

1. 用 **Playwright 通过 CDP 接管**你已经登录的 Chrome（`connect_over_cdp`），复用登录态，绕过反爬。
2. 打开 `https://www.tiktok.com/@<username>`。
3. **监听网络响应**，拦截 `/api/post/item_list` 这个接口返回的 JSON，从中解析每个视频：
   - `video.cover` / `originCover` / `dynamicCover` → 封面图 URL
   - 只保留 `author.uniqueId == 目标博主` 的条目，避免把"推荐流"里别人视频误算进来。
4. 抓够 `max_covers`（默认 5）个就停。
5. 失败会返回 None，主程序记为该账号 failed（不会中断全局）。

> 为什么用浏览器拦截而不是纯 API？TikWM 的 `/user/posts` 经常被 Cloudflare 403，浏览器拦截更稳。

## 六、核心质检 qc_image() 逐项详解

### 6.1 读图与尺寸
- 用 PIL 打开校验文件完整性，记录宽高；损坏 → 直接 C。

### 6.2 人脸检测（InsightFace / buffalo_l）
- 模型：`buffalo_l`，`det_size=(640,640)`，`CPUExecutionProvider`。
- 为提速：先把图缩到长边 ≤1024 再检测，检测完把 bbox **按比例还原**回原图坐标。
- 取**面积最大的人脸**作为主脸，记录：人脸框宽 `face_width`、高 `face_height`、置信度、以及人脸区域局部清晰度 `face_blur_score`（对人脸 crop 求 Laplacian 方差）。

### 6.3 模糊度
- 整图灰度 `Laplacian 方差` 作为清晰度分 `blur_score`。越大越清晰。

### 6.4 字幕 / 水印 / 文字浮层（tiktok封面水印筛选.py）
两层子检测，任一命中即视为"有叠加文字"：

1. **`detect_watermark(bgr)`**：RapidOCR 全图 OCR，
   - 统计每段文字的"白色程度 / 深色像素比例"及所在位置；
   - 判定是**水印/logo**（四角/边缘、四角高对比）→ `status=watermarked` → C。
2. **`detect_text_overlay(bgr)`**：更精准的"烧录字幕"判定——**不限制位置**：
   - 只要 OCR 框内同时满足"**白色字**（V>195,S<60 占比>6%）+ **深色描边**（V<75 占比>5%）"，
   - 就判定为"编辑加进去的字幕/文字浮层"→ 命中。
   - 关键设计：真实产品包装/衣服上的彩色字（如 KFC、MILO）没有"白字+黑描边"特征，**不会误判**；而短视频常见的中文美食字幕（如"抹茶千层""到手还是6个"）正是白字+黑描边，能稳定抓到。
   - 悬浮**图片**贴纸（无文字）此步抓不到，交给 6.5。

### 6.5 贴纸 / 图片浮层（vlm_overlay.py — 本地视觉模型）
- 模型：**SmolVLM-500M-Instruct**，CPU、float32、多线程，长边缩到 448 再推理，生成 4 个 token。
- 输入一张图 + 一句判定提示：
  > "这张图是否有视频编辑叠加的内容：白色描边字幕、水印/logo、装饰文字，或**漂浮在空中的商品图片/贴纸**（真实产品包装上的印刷文字不算）。只回答 yes / no。"
- 回答含 `yes` → 判"疑似贴纸/浮层(视觉模型)" → C。
- **只在通过了人脸+清晰度+OCR 文字关卡的图**上运行（省时，避免对已判 C 的图浪费算力）。
- 为什么用它：纯图像算法（锐利孤岛、平滑背景包围等）区分"贴纸浮层"误报率极高（实测 25/65），只能靠视觉模型做语义判断。

### 6.6 评级决策顺序（qc_image 末尾）
按顺序短路判定，命中即定性：

```
1. face_count == 0                         → C  未检测到人脸
2. 人脸宽或高 < 128px                       → C  人脸尺寸不足128px
3. blur_score < 35                          → C  严重模糊
4. detect_watermark == watermarked(clear)  → C  检测到水印/Logo
5. 字幕/文字浮层 detect_text_overlay 命中   → C  疑似字幕/浮层
6. 以上都过 → 跑视觉模型 vlm_check：
       yes                                 → C  疑似贴纸/浮层(视觉模型)
       no  → 再检查 B 条件：
             - 水印为 suspect            → 记 B（疑似水印/Logo）
             - face_blur_score < 18      → 记 B（人脸模糊）
             - 边长 < 256px              → 记 B（分辨率偏低）
             有任何 B 条件 → B；否则 → A
```

### 6.7 关键阈值一览（都在 `tiktok博主图片采集.py` 顶部常量）

| 常量 | 值 | 含义 |
|---|---|---|
| `FACE_MIN` | 128 | 人脸框宽、高都必须 ≥128px |
| `BLUR_THRESHOLD` | 35.0 | 整图 Laplacian 低于此值判"严重模糊" |
| `FACE_BLUR_THRESHOLD` | 18.0 | 人脸局部清晰度低于此值记 B"人脸模糊" |
| `MIN_IMAGE_SIDE` | 256 | 短边小于此记 B"分辨率偏低" |

## 七、去重与断点续跑

- **SHA256 去重**：同一张图在多帖重复出现，按文件哈希去重，重复的删掉并记 `SHA256重复`（C）。
- **checkpoint**（`output_covers/checkpoints/checkpoint.json`）：记录每个账号已处理的 `done_posts` 和 `seen_hashes`，中断后重跑会跳过已完成部分，实现增量续跑。
  - 注：本次清理为"只留最后一轮结果"，checkpoints 目录已删除；下次运行会自动重建。

## 八、输出结构

```
output_covers/
├── <账号名>/
│   ├── A_初筛通过/      # 干净可用（有人脸、清晰、无文字/贴纸叠加）
```

`summary.xlsx` 字段包含：账号、帖子、尺寸、人脸数/框/尺寸/置信度、模糊分、水印/logo/滤镜状态、等级、复核原因等，可直接筛选人工终审。

## 九、典型"被筛掉"的原因对照

| 复核原因 | 触发环节 | 例 |
|---|---|---|
| 未检测到人脸 | InsightFace 0 人脸 | 纯食物号封面（如 fish9960、ikbalnm） |
| 人脸尺寸不足128px | 人脸太小 | 群体/远景 |
| 严重模糊 | Laplacian<35 | 视频软帧 |
| 检测到水印/Logo | OCR 水印 | 边角台标、账号水印 |
| 疑似字幕/浮层 | 白字+黑描边 | "抹茶千层""到手还是6个"等中文字幕 |
| 疑似贴纸/浮层(视觉模型) | SmolVLM 判 yes | 头顶漂浮的商品图/糖果贴纸 |

## 十、性能与硬件事实

- 本机**无 NVIDIA/CUDA 显卡**，只有 Intel 集显，PyTorch 无法用它加速。所有模型均 **CPU 运行**。
- 视觉模型 500M 在 CPU 上约 **10–13 秒/张**（仅对通过前几关的图运行）；2.2B 模型约 50 秒/张，太慢不可用。
- 因此整批（含下载+人脸+OCR+视觉模型）一次约十几分钟。
- 若要"又快又准"，唯一可行路线是接入**云端视觉 API**（需 key）；本地 CPU 无法同时做到快与高准。

## 十二、已知局限

1. **视觉模型 500M 能力有限**：偶有漏判（部分外语字幕靠 OCR 那层补）与个别误判；准确率约 80–90%。
2. **贴纸浮层**只能靠视觉模型，无 GPU 时较慢。
3. **滤镜/美颜**仍是启发式，进 B 待人工。
4. TikTok 接口/反爬可能波动，抓取失败会记 failed 并可重跑续抓。
5. A 档是机器初筛，最终以人工确认为准。
